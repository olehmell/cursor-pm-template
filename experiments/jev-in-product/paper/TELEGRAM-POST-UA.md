# Чернетка поста для @olehmell_kitchen

Пробував Jev від TypeSafe — і трохи переосмислив, нащо він взагалі

Коротко: це не чат-модель. Ти даєш стан (лист, тікет, шматок PRD) і вузькі питання з готовими відповідями — так/ні з імовірністю, вибір з списку, оцінка по шкалі. Відповіді прилітають пачкою за сотні мс, а далі вже твій код роутить / лейблить / ескалює. Текст воно не пише.

Ціна: **$0.042 / 1M input**, output безкоштовний. Багато питань на один state майже не роздуває рахунок — state читається раз.

Куди вже тикають (близько до продукту):

1. **Лейблінг пошти/тікетів** — OOO/spam vs живий клієнт, черга billing/account/tech. There There (Laravel): лейбл раз → workflow по колонці в БД, без LLM-summary на кожен bounce.
2. **Роутинг на агента** — intent + складність + confidence → код / specialist LLM / людина.
3. **Лейблінг запитів юзерів** — intent, product area, refund/churn, теми у feedback.
4. **Харнес** — який skill/subagent вантажити, чи потрібен skill взагалі, guardrails і citation check після LLM.

Я прогнав це на своєму PM-template (інтерв’ю → PRD → прототип), гілка `experiment/jev-product-tasks`.

На пальцях:
- «Класифікатор для звіту» (одна тема + severity на цитаті) — слабо: ~69% / ~34% exact, на межах severity інколи стрибає.
- Вузькі продуктовий гейти (MVP-скоуп? метрика вимірювана? екран тягне гіпотезу?) — **90–100%**, на 5 повторах майже не плаває.
- Роутер скілів (analysis / PRD / prototype / нічого), 48 запитів: wrong route **0%**, needless ~**10%**, overall ~**98%**.

Usage з моїх прогонів (~280 відповідей, ~291k input, разом зі stability ×5): близько **$0.012**. На такій ціні inbox-лейблінг і роутинг агентів — нормальна функція в коді, не «дорогий LLM-крок».

Висновок: Jev не замінює Claude/Codex у PM. Він — купа сенсорів у софті (лейбл / роут / verify), а генерацію лишаєш LLM. Спочатку виміряли не те; підкрутили форму питань — і картинка змінилася.
