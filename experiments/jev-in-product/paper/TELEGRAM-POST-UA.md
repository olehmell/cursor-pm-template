# Чернетка поста для @olehmell_kitchen

Пробував Jev від TypeSafe — і трохи переосмислив, нащо він взагалі

Спочатку теорія коротко, бо без неї здається, ніби це «ще одна LLM, тільки дивна».

Jev — це System One модель (натяк на Канемана): швидкі структуровані рішення для софту, а не генерація тексту. Ти даєш `state` (текст/JSON) і пачку typed-питань — Choice / Score / Noul (ймовірність «так»). Воно відповідає на всі питання паралельно за ~сотні мс, з імовірностями й confidence. Код далі робить if/роутинг/ескалацію. Текст воно не пише — і це фіча, не баг.

Ціна зараз: **$0.042 за 1M input tokens**, output безкоштовний (too cheap to meter). Платиш лише за те, що закинув у state+questions. Багато питань на один state — майже той самий input, бо state читається раз.

Далі — куди люди вже тикають це в реальності (близько до продуктового світу):

1. **Лейблінг пошти/тікетів.** Не OOO і не spam → у чергу. Helpdesk There There на Laravel так і зробив: Jev один раз ставить лейбли, далі workflow дивиться в колонку БД, без LLM-summary на кожен bounce.
2. **Роутинг на агента/чергу.** Intent + складність + confidence → deterministic код / specialist LLM / людина. Класичний intent routing з їхніх docs.
3. **Лейблінг запитів юзерів.** Intent, product area, refund/churn сигнали, теми у feedback — той самий м’яз, що в research transcripts у їхньому use-case map.
4. **Оркестрація харнесу.** Який skill/subagent вантажити, чи взагалі потрібен skill, continue/retry/ask/stop, guardrails і citation check після LLM.

Я взяв свій PM-template (аналіз інтерв’ю → PRD → прототип) і прогнав серію експериментів у гілці `experiment/jev-product-tasks`.

Що вийшло на пальцях:
- Коли просив Jev бути «класифікатором для звіту» (одна тема + severity на цитаті з інтерв’ю) — так собі: theme ~69%, severity exact ~34%. Плюс на межах severity інколи стрибає між high/medium.
- Коли зробив вузькі noul-гейти під продукт (MVP-скоуп PRD? метрика вимірювана? екран тягне гіпотезу?) — уже **90–100%** на маленьких сетах, і стабільність на 5 повторах майже ідеальна.
- Роутер скілів шаблону (analysis / PRD / prototype / нічого) на 48 запитах: wrong route **0%**, needless ~**10%**, overall ~**98%**. Ось це вже схоже на сенсор у софті, а не на «напиши мені інсайти».

Грубий чек по usage з моїх прогонів (~280 live-відповідей з usage, ~291k input tokens, включно зі stability ×5): близько **$0.012** — тобто центи, не долари. На такій ціні можна ганяти inbox-лейблінг і роутинг агентів як звичайну функцію в коді, а не як «дорогий LLM-крок».

Висновок для себе: сила Jev не в тому, щоб замінити Claude/Codex у PM-воркфлоу. Сила — вставити в код купу вузьких сенсорів (лейбл / роут / verify), зібрати відповіді правилами, а генерацію лишити LLM. Ми спочатку виміряли не те; потім підкрутили форму питань — і картинка стала іншою.

Хто вже чіпав System One в сапорті чи агентному роутингу — киньте в коменти, куди вбудували. Мені цікаво звірити з моїм PM-сетапом.
